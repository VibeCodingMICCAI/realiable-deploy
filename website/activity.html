MICCAI tutorial · activity guide

From Vibe Coding to Trustworthy AI

Full activity sheet for facilitators and participants

Audience: researchers with a working AI prototype · Time: ~30–40 minutes · Example: knee MRI segmentation (cached nnU-Net demo)

Learning goals

  1. Separate model testing from software testing.
  2. Name what makes a prototype reproducible.
  3. Use better prompts to generate tests, and score AI-generated tests.
  4. Match evidence to intended use (demo ≠ open-source ≠ clinical).

1. Choose intended use

Personal prototype, live demo, publication/open-source, or clinical/production. This shapes final recommendations only — everyone walks the same path.

2. Testing checklist

Model: Is performance acceptable?
Software: Does load → preprocess → predict/cache → save stay correct and stable?

Notice: smoke, unit, integration, regression, invalid-input.

3. Reproducibility checklist

Clone → Install → Run one command → Reproduce the example result

Environment, pins, checkpoint, sample data, seed, code version, one documented command.

4. Run the lab

  1. Run demo — cached MRI → overlay + Dice
  2. Run smoke test — output exists, shape, labels
  3. Reproduce example — provenance (hashes, Dice match)

Sample-mode banner? Start python scripts/tutorial_lab.py locally for live runs.

5. Score AI-generated tests

Same task, three prompts (weak / medium / strong):

  1. Read prompt + generated test
  2. Score the 6-point rubric (Yes/No)
  3. Compare with answer key + critique
  4. Optional: copy the strong prompt into your assistant
#Rubric item
1Calls real path
2Fixed example (examples/case_001)
3Observable asserts (not assert True)
4Regression anchor (metrics.json / hash)
5Failure modes (invalid inputs)
6Tutorial constraints (no download / GPU; CI-friendly)

Teaching point: prompt quality drives test quality — a high score still needs a real run.

6. Pack what you need

For Demo / Open-source / Clinical: pack essentials, leave overkill in the pool (e.g. regulatory items for a conference demo), then check packing.

7. Summary

Review checklist counts, your test scores, packing scores, and “consider adding” items. Educational only — not clinical certification.

Facilitator notes

  • Open with: “The model already works on my laptop — what else do we need?”
  • Live-demo the lab once; use sample mode if installs are hard.
  • On the weak prompt: “Would a broken pipeline still look green?”
  • On packing: put “clinical validation” in the demo bag and discuss.
  • Close: demo-ready ≠ publication-ready ≠ clinical-ready.

What this is not

  • Not an nnU-Net training tutorial
  • Not a claim of SOTA segmentation
  • Not regulatory or clinical certification guidance
